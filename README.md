# Описание проекта

Прототип двумерной сцены на Godot с использованием C#, демонстрирующий порождающий паттерн проектирования Builder (Строитель). 

В проекте реализованы два типа врагов: гоблин и дракон. Они отличаются запасом здоровья, уроном, скоростью и спрайтом. Каждую секунду на поле появляется случайный враг, который движется к центру поля. Основная задача проекта — показать взаимодействие Продукта, Строителя, Конкретных строителей и Директора.

## Структура

**Сцены находятся в папке `scenes/`:**

1. **field** — основная сцена формата `Node2D`.
   Содержит фон поля `Sprite2D` с градиентной текстурой и узел `EnemySpawner`. Границы фона используются для выбора начальных позиций врагов, а его центр — как точка назначения.

2. **Enemy** — общая сцена врага формата `CharacterBody2D`.
   Содержит `Sprite2D`, круглую коллизию `CollisionShape2D` и скрипт `Enemy.cs`. Одна сцена используется для обоих типов врагов: внешний вид и скорость определяются назначенным ресурсом `EnemyData`.

**Текстуры находятся в папке `resourses/`:**

1. **Goblin_sprite.png** — спрайт гоблина.

2. **Dragon_spite.png** — спрайт дракона.

## Скрипты

**Основные скрипты находятся в папке `scripts/`:**

1. **Enemy.cs** — хранит ресурс характеристик `Data` и точку назначения `targetPosition`. Метод `setEnemyData()` назначает характеристики, а `applyData()` применяет текстуру через ресурс. Метод `_PhysicsProcess()` перемещает врага к цели с помощью `MoveToward()`, учитывая скорость `Data.speed` и время физического кадра.

2. **EnemyData.cs** — ресурс формата `Resource`, содержащий здоровье `hp`, урон `damage`, скорость `speed` и текстуру `texture`. Поля доступны в инспекторе через `[Export]`. Метод `applyTo()` устанавливает текстуру дочернего узла `Sprite2D`. Скорость используется скриптом врага при движении; здоровье и урон сохраняются в ресурсе, но боевая механика в текущем проекте не реализована.

3. **EnemyBuilder.cs** — абстрактный базовый строитель. Хранит текущий продукт `_product`, объявляет абстрактные методы `buildHp()`, `buildDamage()`, `buildSpeed()` и `buildSprite()`. Метод `getResult()` возвращает готовый ресурс и создаёт новый продукт для следующей сборки. Каждый враг получает отдельные характеристики.

4. **GoblinBuilder.cs** и **DragonBuilder.cs** — конкретные строители, переопределяющие все шаги. HP, урон, скорость и текстура доступны в инспекторе дочерних узлов `EnemySpawner/GoblinBuilder` и `EnemySpawner/DragonBuilder`.

5. **EnemySpawner.cs** — управляет периодическим появлением врагов. В `_Ready()` получает строителей из сцены и запускает таймер. Метод `SpawnRandomEnemy()` выбирает строителя, `construct()` выполняет шаги сборки, а `spawn_enemy()` создаёт врага, назначает характеристики и размещает его на поле. Поля `enemyScene`, `enemySize` и `spawnInterval` доступны в инспекторе. По умолчанию размер спрайта равен 64 пикселям, интервал спавна — одной секунде.

## Компоненты

**Роли участников паттерна Builder распределены следующим образом:**

1. **Продукт — EnemyData.** Хранит результат построения: набор характеристик и текстуру врага.

2. **Строитель — EnemyBuilder.** Определяет общие шаги заполнения продукта и способ получения результата.

3. **Конкретные строители — GoblinBuilder и DragonBuilder.** Выполняют одинаковые шаги, но задают разные значения и загружают разные текстуры.

4. **Директор — EnemySpawner.** Вызывает методы через общий тип `EnemyBuilder` в фиксированном порядке: `buildHp()`, `buildDamage()`, `buildSpeed()`, `buildSprite()`, затем `getResult()`. Конкретные значения характеристик задаются внутри строителей. Метод `construct()` собирает характеристики, а `spawn_enemy()` создаёт врага на сцене.




## Ход игры

При запуске сцены на поле нет врагов. Примерно через одну секунду таймер создаёт первого противника, затем появление повторяется каждую секунду. Для каждого врага случайно выбирается один из двух строителей.

Враг появляется внутри границ фона с отступом в половину заданного размера спрайта и движется к центру поля. Дракон перемещается вдвое быстрее гоблина. После достижения центра враги остаются на месте и накапливаются, а создание новых продолжается до остановки проекта.

Условия победы и поражения, атаки и уничтожение врагов в текущей реализации отсутствуют. Сцена предназначена для наблюдения за результатом работы паттерна Builder.

## Запуск

1. Установить Godot 4.7.2 с поддержкой .NET и .NET SDK 8.
2. Импортировать `project.godot` в Godot и открыть проект.
3. Собрать C#-проект кнопкой сборки в редакторе.
4. Нажать F6 для запуска открытой сцены `scenes/field.tscn` или F5 для запуска проекта: поле уже назначено главной сценой.

На поле появятся гоблины и драконы, которые движутся к центру. Бой не реализован. Для изменения характеристик выбрать нужного строителя в дереве сцены, для изменения интервала спавна — `EnemySpawner`.
